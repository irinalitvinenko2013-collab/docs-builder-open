# QA-чеклист перед отдачей PDF

Грузится субагентом `pdf-builder` на этапе само-QA — по требованию, не каждую сессию.

> **Обучающие/пошаговые гайды:** дополнительно действует `.claude/rules/learning-guide-spec.md`.
> Проверять отдельно: ОДИН крупный читаемый скрин на страницу (без пар рядом); рамки/стрелки
> «куда жать» точно на кнопках, номер рамки = номер шага; пошаговый мануал по каждому разделу
> на живом примере; заполнение ≥⅔ без пустого низа; легенда не обрезана и не на подвале.
> **Два баг-граблей (из практики, проверять каждый раз):**
> (1) **скрин не обрезан по бокам** — на `<img>` скрина ЗАПРЕЩЕНЫ `object-fit:cover` и
> `min-height`/фикс. высота (зумят и режут картинку, прячут номерные бейджи); только
> `width:100%;height:auto`. (2) **каждая номерная рамка лежит на своей кнопке** — координаты
> мерены по сетке (шаг ≤0.02), а не «на глаз»; сверять на готовом PDF, особенно мелкие кнопки
> (START/STOP, кол-во/период, иконки) и сдвинутые состояния.

## Двойной аудит после рендера (ОБЯЗАТЕЛЕН ВСЕГДА, не пропускать)

**А. Визуальный аудит** — скриншоты КАЖДОЙ страницы (`qa_screenshots.py`) просмотреть глазами:
- [ ] Ни один блок не вылезает за границы листа (горизонтально и вертикально). Особо проверять флекс-ряды из многих плашек со стрелками и фиксированной шириной колонки — частый виновник.
- [ ] **Скрины не обрезаны по бокам** (обучающие гайды): видны все номерные бейджи, поля и кнопки целиком. Симптом обрезки — `object-fit:cover`/`min-height` на `.shot img`; должно быть `width:100%;height:auto`. Сверять по рендеру, а не по HTML.
- [ ] **Каждая номерная рамка физически лежит НА своей кнопке** (обучающие гайды): номер рамки = номер шага легенды, рамка обводит именно тот элемент. Проверять по готовому PDF; особое внимание мелким кнопкам (START/STOP, кол-во/период, иконки копировать/экспорт) и состояниям, где кнопка сдвинута. При сомнении — увеличить кроп рамки и сверить с координатной сеткой.
- [ ] Все изображения отрисованы: нет alt-текста/плейсхолдеров вместо логотипа, фото, AI-картинок (симптом рендера не из корня проекта).
- [ ] Графики Chart.js не пустые, схемы дорисованы, иконки на месте.
- [ ] Все пункты визуальных требований ниже (баланс, заполненность, обложка, подвалы) сверены по скриншотам, а не «по памяти».
- [ ] 🔒 **Личное на кадрах:** если скрины сняты с настоящего экрана (запись экрана, свои
      скриншоты) — просмотрены глазами на почту, имена, телефоны, счета, суммы, чужие
      компании, содержимое переписок и всплывшие уведомления. Чужое замазано
      (`annotate_shots.py --замазать`), список замазанного назван пользователю. Кадр,
      который нельзя показывать целиком, — страница убрана, шаг оставлен словами.

**Б. Аудит текста (фактчекинг + грамотность)** — выполняет СВЕЖИЙ субагент, не тот, кто верстал:
- [ ] Каждая цифра, исследование, атрибуция: либо есть в источнике (`ingest/normalized.md`), либо проверена в интернете с точным источником. Неверифицируемое — удалить или переписать без цифры. Субагенты-верстальщики склонны выдумывать правдоподобную статистику («Nielsen 2023», «McKinsey 2019») — по умолчанию не доверять.
- [ ] Концептуальные графики/дашборды помечены «пример/концепт», в них нет цифр, выдающих себя за данные исследований.
- [ ] Орфография, пунктуация, опечатки — вычитка всего текста, включая подписи к графикам, подвалы, мелкие подписи.
- [ ] Единый тон по всему документу: без канцелярита и рекламных обещаний; финал — понятное действие, а не повисшая фраза.

## Визуальные требования

- [ ] **Цвета и шрифты — из активного профиля** (`context/theme.css` собран, ни одного жёсткого HEX в вёрстке).
- [ ] **Баланс тёмных и светлых ≈30/70.** На коротком документе точной доли не бывает: считаем
      соблюдённым, если тёмных от 20 до 40 %. Меньше четырёх страниц — достаточно одной тёмной
      (обложка). Округляем до целых процентов, спорить о десятых незачем.
- [ ] **Заполненность меряет скрипт, а не глаз.** Единственный измеритель —
      `qa_screenshots.py` (порог `FILL_MIN`, сейчас две трети): он печатает долю по каждой
      странице и помечает пустой низ. Тёмные страницы-обложки и цитаты не гейтятся — на них
      воздух уместен, их смотрим глазами.
- [ ] **Инфографика — эталонным языком** (скилл `document-design` → «Инфографика»,
      разметка `templates/blocks/infographic.html`): подписи капсом `.viz-cap`, фигура залита
      вторым акцентом, одна-две фигуры на страницу, на каждой светлой странице один тёмный
      якорь `.dark-note`. Каждая фигура опирается на факт из источника: доля шкалы, число
      долей, узел отказа — из текста, а не «на глазок»; неизвестное количество — многоточие
      `.dots`, а не придуманная цифра. Число не дублируется отдельной строкой рядом с фигурой.
- [ ] **Визуальная насыщенность:** каждая светлая контентная страница несёт ≥1 крупный графический элемент (график Chart.js / схема / дашборд / AI-фото / CSS-инфографика). Страниц «таблица+текст» без графики нет. Числа в графиках реальные; концептуальные дашборды помечены «пример».
- [ ] **Чем именно наполнять — решает источник, а не норма.** Есть числа → ≥2 графика и ≥1 схема. Чисел нет (памятка, FAQ, инструкция) → графиков нет вовсе, их место занимают схемы процесса, CSS-инфографика и карточки. Рисовать график там, где данных нет, — значит выдумать данные; это запрещено выше по списку и весит больше, чем норма насыщенности.
- [ ] **Заполненность ≥ 2/3 (единый top-align, без центрирования).** Все светлые страницы выровнены по верху — оформление единообразное. Не хватает до 2/3 — сначала **убрать лишнюю страницу**: короткому источнику честнее выйти плотной памяткой на 5 страниц, чем растянутой на 9. Разбивать материал ради объёма — та же накрутка, что и выдуманные данные. Плотность уже набрана, а место осталось — можно добавить проверяемый факт из интернета (исследование, опрос, пример компании) с краткой атрибуцией; только реальные факты, НИКОГДА не выдумывать цифры и исследования. Исключение — тёмные страницы-цитаты (намеренно центрированы).
- [ ] **Обложка:** логотип и фото автора из активного профиля (`assets/профиль/`), красиво интегрированы в композицию (не «прилеплены»). Профиль без логотипа/фото — блок собирается без них, заглушки не рисуем.
- [ ] **Логотип на тёмном фоне — светлая версия `assets/профиль/логотип-на-тёмном.*`**, БЕЗ белых квадратов/подложек/рамок и без CSS-фильтров. Основная версия `логотип-на-светлом.*` — только на светлых страницах.
- [ ] **На обложке НЕТ метрик автора** (ученики, доходимость, оборот и т.п.) — они живут только на странице «Об авторе».
- [ ] **На обложке нет мета-подписей:** «методичка к уроку N», «№ X из Y», «конспект/рабочая тетрадь», «серия», бейджи-навигация по серии. Только кикер (курс • блок), название, содержательный подзаголовок, фото + имя автора.
- [ ] **Титул собран по канону:** заголовок · «что вы получите» (3–4 строки, каждая — про реальный раздел, без обещаний вроде «за 5 минут») · кликабельное содержание с номерами страниц · автор. Пункты содержания ведут на свои разделы, номера страниц совпадают с фактическими.
- [ ] **Финальная страница:** один призыв крупной панелью во втором акценте, кликабельные контакты автора, блок автора. Призыв не пересказывает разделы.
- [ ] **Автор — на титуле, контакты — на финальной странице** (`.claude/rules/канон-документа.md`). Имя и роль стоят на первой странице, поэтому «не долистает» не работает: читатель знает автора сразу, а адрес получает там, где собрался написать. Блок автора — один, на финальной странице, вместе с призывом; отдельной страницы «Об авторе» нет.
- [ ] **«Что внутри» = кликабельное оглавление.** Каждый пункт — якорь `<a href="#sec-xxx">` на свой раздел; у целевой `<section id="sec-xxx">` стоит совпадающий `id`. Проверить, что в PDF есть внутренние переходы (named destinations) и они ведут на нужные страницы.
- [ ] **Кегль крупный, читаемо с экрана:** основной текст ≥10pt (целевой 10.5pt), мелкие метки/подписи ≥7.5pt (абсолютный пол). Мельче — НЕ принимать (см. скилл `document-design` → «Шрифты и шкала кеглей»).
- [ ] Таблицы и плотные блоки не залезают на подвал. **Переполнение лечим переносом на новую страницу (поток), а НЕ мельчением шрифта:** кегль не опускаем ниже минимума; микро-подтяжка отступов (`td`, верхние) — последнее средство и не ценой кегля.
- [ ] Нижний ряд элементов не липнет к подвалу — странице `padding-bottom: 15mm`.
- [ ] Фото: лицо по центру круга (правка через `object-position` или пересборка `.venv/bin/python scripts/prep_photo.py`).
- [ ] Эмодзи/флаги рендерятся (Chromium берёт Noto Color Emoji из коробки).
- [ ] Все ссылки кликабельны: `python scripts/check_links.py output/output.pdf` (> 0 и совпадает с ожидаемым числом).
- [ ] В `href` всегда полный `https://`; в подписи можно показывать короткий вид.
- [ ] **Одна мысль — одно место.** Если факт (чек приходит автоматически, письмо идёт пару
      минут) сказан в карточке, он не повторяется ещё и в плашке, и в строке-итоге на той же
      странице. Повтор выглядит как наполнитель и съедает доверие: читатель решает, что
      документ раздували. Дублируется — оставить одно, сильнейшее по месту, остальное убрать
      или заменить новым содержанием.
- [ ] **Контакт из профиля не выдаём за службу поддержки.** Если в документе есть шаг «напишите
      нам» — он ведёт туда, куда указано в источнике. Личный контакт автора подписываем как
      личный («написать автору»), а не как «поддержка»: иначе человек ждёт дежурного ответа
      там, где отвечает один живой человек. Источник молчит про канал поддержки — оставляем
      формулировку из источника, без ссылки.
- [ ] Фоны/градиенты на месте (рендер с `print_background=True`).
- [ ] Адреса агрегаторов/сервисов перепроверены — при необходимости добавить сноску-дисклеймер.
