# Сборщик документов — для Codex, Kimi Code и других инструментов

**Полная карта системы — в файле `CLAUDE.md` в этой же папке. Прочитай его целиком: пайплайн,
профили, правила, скрипты, границы.** Здесь — только то, что касается ролей и команд.

## ⛔ Перед тем как менять систему — сохрани версию

**Первое правило, важнее всех остальных.** Прежде чем править файлы системы (правила,
шаблоны, роли, скрипты, инструкции, оформление):

```bash
.venv/bin/python scripts/версия.py сохрани "что собираюсь менять"
```

Без этого правка необратима. Разрешения не спрашивай — сохрани и скажи одной строкой.
Личное (профили, принесённые файлы, готовые документы) в версию не попадает.

Просят вернуть как было → `версия.py список`, затем `версия.py откати` (или `--на N`).
Откат ничего не стирает: вся история остаётся на месте.

## Роли в системе — их три, и они есть у каждого инструмента

Одно и то же описание роли лежит в трёх форматах, чтобы система работала одинаково везде.
Источник истины — `.claude/agents/*.md`; остальные два собираются из него скриптом
`scripts/sync_agents.py`, руками их не правят.

| Роль | Что делает | Claude Code | Codex | Kimi Code |
|---|---|---|---|---|
| `source-extractor` | ссылка, чужой PDF, запись, скринкаст → чистый текст | `.claude/agents/` | `.codex/agents/*.toml` | `.kimi-code/agents/*.md` |
| `pdf-builder` | вёрстка и рендер документа | то же | то же | то же |
| `auditor` | приёмка готового PDF **свежим взглядом** | то же | то же (режим только чтения) | то же |

**Codex:** роли зарегистрированы в `.codex/config.toml`, вызываются инструментом `spawn_agent`;
дождаться результата — `wait_agent`, посмотреть живых — `list_agents`. Набор инструментов
у разных версий отличается: чего нет под рукой — просто не используй, на работу это не влияет.
**Kimi Code:** роли лежат в `.kimi-code/agents/`, главный агент делегирует им задачи сам.

Если в твоём инструменте субагентов нет вообще — выполняй те же файлы сам, как инструкцию.
Тогда **этап приёмки всё равно делай отдельным проходом по готовому PDF**, а не по памяти о
вёрстке: открой скриншоты страниц и перечитай текст заново, будто видишь его впервые.

## ⛔ Главное правило приёмки

**Документ проверяет не тот, кто его верстал.** Автор вёрстки свою ошибку не видит — он уже
знает, «как задумано», и глаз достраивает недостающее. Поэтому после рендера зови `auditor`
(или, если субагентов нет, делай отдельный проход). Это не формальность: на этом ловятся
выдуманные цифры и обрезанные блоки.

## Команды

Слэш-команд у тебя может не быть — тогда просто открой файл и следуй ему:

| Команда | Файл с инструкцией |
|---|---|
| `/setup` — завести или поправить профиль | `.claude/commands/setup.md` |
| `/pdf` — собрать документ | `.claude/commands/pdf.md` |

Скиллы и правила — обычные текстовые файлы: открывай и применяй, даже если твой инструмент
не знает слова «скилл».

## Всё остальное — без изменений

Версия перед правкой системы, профиль обязателен, слаг на каждую работу, ни одного жёсткого
цвета в вёрстке, данные автора только из `context/автор.md`, честные границы вслух. Скрипты запускаются одинаково:
`.venv/bin/python scripts/<имя>.py`.

🪟 **Windows:** питон окружения там — `.venv/Scripts/python.exe`. Установка создаёт
`.venv/bin/python` мостиком к нему, поэтому команды пишутся одинаково на любой системе.
Мостика нет — подставь путь `Scripts` и скажи об этом пользователю, а не молча.

⛔ Файлы создавай инструментом записи файлов, не heredoc-ом (`cat <<'EOF' ...`) — на
Windows-шелле (PowerShell/cmd) он не работает.

Один и тот же документ на любом инструменте должен собираться одинаково. Что-то не заводится —
скажи прямо, не делай вид, что так и надо.
